### Знахідки

1. **`strict: true` на інструментах — вимкнено.**
   - Перший запит після появи схем чекав першого токена 22,2 с: API компілює граматику схем і тримає її 24 год від останнього використання.
   - Кожен наступний запит — у середньому на ≈ 0,35 с повільніший: p50 0,96 с проти 0,61 с, p90 2,16 с проти 0,82 с.
   - Точність без strict не гірша: 98 % проти 96 %, усі аргументи відповідали схемам.
   - Рішення: без strict; межі значень перевіряє код (крок 1.4). Порівняти знову — `npm run evals -- --strict`.
2. **Виклик, записаний текстом.** У першому прогоні на «давай попередню пісню» модель написала `"Попередня пісня." and media {"action": "previous"}` текстом, наслідуючи формат прикладів у промпті. Синтезатор озвучив би це, а дія не відбулася б.
   - Виправлено: приклади у форматі `say:` / `call:` з поясненням, що `call:` — справжній виклик, і правило «назву інструмента й аргументи в тексті не писати».
   - Оцінка набору тепер позначає такі відповіді окремою причиною.
   - Для продукту (крок 1.5): core не озвучує текст, у якому є назва інструмента з аргументами, і вважає хід збоєм.
3. **«Пам'ять» — це оперативна пам'ять.** На «що зараз їсть найбільше пам'яті» модель рахувала розмір теки на диску. У промпт додано значення слів «пам'ять», «оперативка», «місце», «диск».
4. **Незалежні дії разом.** Усі 4 команди з кількома простими діями («відкрий ютуб і зроби гучність сорок») модель виконала однією відповіддю з двома викликами. Ризик «хід обривається після першої простої дії» не підтвердився. Кроки, що залежать від результату (`find_files` → `file_op`), модель робить по черзі й бере шляхи з результату, а не вигадує.
5. **Помилка, що лишилась:** на «запусти ту програму, яку я вчора відкривав» модель відповіла твердженням без питання: «Не вказав, яку програму ти відкривав вчора.» Промпт під один випадок не підганяю; повторюється — правимо.

### Затримка для голосу (N1)

Ціль N1 — від кінця фрази до першого звуку p50 ≤ 1,5 с. Наближений бюджет: розпізнавання ≤ 0,8 с (крок 0.3) + перший токен Haiku 0,61 с + перший звук Piper ≤ 0,2 с ≈ 1,6 с. Це трохи понад ціль, тож спекулятивний старт Whisper на паузі (02-voice.md) потрібен. Остаточний замір — крок 0.7.

- Власник переписує формулювання команд у `evals/commands.json` під свою мову; після цього — повторний прогін.
- Ін'єкції — окремий набір на кроці 1.8.

## 0.3 · розпізнавання мови

Прогін: `npm run stt` — 50 записаних команд власника (гарнітура JBL, 16 кГц), модель тримається завантаженою, перший виклик розігріває й не рахується. Точність — головна мірка: `npm run evals -- --texts` дає Haiku розпізнаний текст замість еталонного і перевіряє, чи дія та сама. Цілі кроку: ≥ 90 %, фраза ~5 с — ≤ 0,8 с, вміщається у 2 ГБ відеопам'яті, без Build Tools і мережевого порту.

Тексти й час кожної команди — `.data/stt/`; прогони Haiku — `evals/results/2026-10-03T23-34-19.json` (Parakeet) і `2026-10-03T23-35-52.json` (Whisper).

### Знахідки

1. **Whisper на GTX 960 повільний.** Майже весь час — кодувальник: він завжди обробляє вікно 30 с, 1,66 с на фразу будь-якої довжини; текст після нього — 4 мс на слово. Коротше вікно (`-ac`) пришвидшує — 0,56 с при 10 с, 0,43 с при 7,7 с, — але якість нестабільна, а при 5 с модель вигадує слова.
2. **Підказка назв (initial prompt) Whisper погіршує:** 11 дослівних замість 14, «Banshee» стало «Bunchy». Без підказки.
3. **Parakeet швидкий, але плутає мову.** Короткі фрази інколи пише польською латинкою: «Wymkny zwuk», «Pozwone mamie». Мову йому не задати — він визначає її сам.
4. **Важкі випадки спільні для обох:** «тєлєгу», «вс код», «пів гучності», «гучність на повну», «вирубай», шлях `D:\temp\notes.txt` і «з флешки E на диск D». Це назви зі словника власника й сленг — їх лагодить словник назв і виправлення власника (етап 2), а не вибір моделі.
5. **Правило в промпті «читай голосовий текст на слух»** дало 76 % замість 72 % на Parakeet — у межах шуму, одна команда зламалась. Не лишили.
6. **Збірки й пам'ять.**
   - whisper.cpp під CUDA 11.8 без `cublas64_11.dll` — відеокарту не бачить і мовчки рахує на процесорі. Під CUDA 12.4 працює: ядра `sm_50` підходять GTX 960. Готової збірки під Vulkan для Windows x64 немає.
   - Перший запуск кожного варіанта — до 9 с розгону відеокарти; у продукті — прогрів під час старту.
   - whisper.cpp має лише готові `whisper-cli` і `whisper-server`: у процесі Node без Build Tools — тільки через `whisper-server` на localhost, а це окреме рішення власника.
   - `sherpa-onnx-node` ставиться без Build Tools і працює в процесі, без порту, але Parakeet тримає в RAM ≈ 780 МБ — більше за ціль N6 (500 МБ у спокої на весь Banshee).
7. **Затримка N1** (p50 ≤ 1,5 с від кінця фрази до першого звуку): з Whisper ≈ 1,67 + 0,61 + 0,2 ≈ 2,5 с — не вкладається; з Parakeet ≈ 0,47 + 0,61 + 0,2 ≈ 1,3 с — вкладається.

### Рішення

Цілі кроку не досягає жоден варіант: Whisper — точніший, але втричі повільніший за ціль; Parakeet — укладається в час, але точність 72 % і пам'ять понад N6. Вибір — за власником, варіанти — у 06-roadmap.md, «Відкриті питання». Крок 0.3 закриється після рішення.

**Рішення власника 2026-10-04:** варіант 1 — Parakeet на процесорі. Точність піднімаємо на кроці 2.2 словником назв, гарячими словами sherpa-onnx і виправленнями власника. Запасний — варіант 3: Whisper на відеокарті лише для команд, які Haiku не зрозумів. Ціль N6 переглянуто до 1,5 ГБ. Крок 0.3 закрито.
